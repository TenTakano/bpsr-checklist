# デザインブリーフ: メイン画面

## 画面の主目的

複数キャラクター横断で残タスクを俯瞰しながら、その場で消化チェックを入れる（俯瞰と記録が不可分に同時にこなせることが、参照元リポジトリに対する本プロジェクトの独自価値）。

## 情報分類

- 必須情報
  - タスク名の全文（固定幅で省略せず、可変幅+折り返しで表示する）
  - タスク色（行頭の色バー）
  - キャラクター列（全キャラを横並びで一望できること）
  - チェック状態（セル全体の背景変化で表現し、マトリクス俯瞰時に達成分布が面で見えること）
  - カテゴリ区分: デイリー / ウィークリー / マイルストーン（期限なし・リセットされない長期目標やイベント準備。ユーザー追加タスクを含む）
- あったら便利
  - サマリーパネル（カテゴリごとの全体進捗バー + キャラ別達成数）
  - セクションごとの達成数表示（例: 6 / 18 完了）
  - 詳細カウント表示（回数タスクをタスクごとの設定で選択式に。既定はチェックボックス）
  - 並べ替え・表示タスク設定・タスク追加への導線
  - テーマ切替（ライト/ダーク）
- 不要
  - 常時表示の −/＋ カウンター（回数を積み残すケースはまれ。詳細カウント表示を選んだタスクでも取り消し − はホバー時のみ表示）
  - タスク補足説明の常時強調表示（タスク名に従属する淡色の小さめテキストに落とす）

## CTA分類

- 主要CTA
  - チェックセルのクリック（セル全体がクリック領域。1クリックで完了記録）
  - 詳細カウントセルのクリック（1クリックで +1、max 到達で完了扱い）
- 副CTA
  - タスク追加（各セクション末尾のゴースト行「＋ タスクを追加」。クリックで追加モーダルを開き、追加先カテゴリは開いたセクションが既定。モーダル自体のデザインは別画面として企画する）
  - 並べ替えハンドル（行左端の専用細列。ドラッグ + ホバー時に強調）
  - 表示タスク設定（セクションヘッダー右端）
  - 設定・テーマ切替（ヘッダー右端）
- 補助情報
  - アプリ名・説明文（コンパクトな1行ヘッダー内）
  - ステータスバナー
  - 進捗数値・プログレスバー（サマリーパネル、セクションヘッダー）

## 参考サービス分析

参考: 同ジャンルのキャラクター別チェックリストサービス（サービス名はローカルの CLAUDE.local.md 参照）の実物スクリーンショット（1440px幅）に基づく分析。

### 構造

- 縦の情報階層は「グローバルナビ → 通知帯 → サマリーパネル（進捗%・集計）→ フィルタ/グルーピング行 → 作業領域（キャラクターカードのグリッド）」。粒度の大きい集計から小粒度の個別チェック項目へ、上から下に分解される構造
- サマリーパネルは横長のプログレスバー2本が視覚的重心となり、視線を作業領域へ導く起点になっている
- 作業領域は同一サイズ・同一構造のユニットが規則的に並ぶリピートパターンで、Z字/グリッドスキャンを誘導する。ユニット内では名前+数値（アイテムレベル）が最大の文字サイズで最上部に置かれ、最初の着地点になる
- 情報密度は非常に高い（1画面に18キャラ×10行超のテキスト）。密度を許容するため、各行は「チェックボックス + 短い名詞 + 数値バッジ」の最小構成に切り詰め、区切り線・背景色変化などの装飾をほぼ排して行間を詰めている
- ページ全体に対する操作系メタ機能（並べ替え・ビュー切替等）は、コンテンツ本体のグリッドを崩さない別レイヤー（右端のフローティング縦型パネル）に分離されている
- 本プロジェクトへの翻訳: キャラごとのカード分割は採らず（横断俯瞰の独自価値を損なうため）、「サマリー → セクション → 密なマトリクス行」の階層構造・密度の捌き方・操作系の分離を移植する

### スタイル

- 文字サイズの階層は浅く約3段階（大: 名前/レベル、中: セクション見出し、小: タスク名・数値バッジ、最大でも18px前後）。極端なサイズ差ではなく太字の有無で階層を作るミニマルな手法
- 数値は本文と同系統のサンセリフで統一し、特殊な書体・カラーは限定的
- 余白は用途で使い分ける: 作業領域内の行間・要素間は密（4〜8px程度）、ユニット間のガターは行間より相対的に広く取って区切りを明確化、サマリー等の非作業領域は 16〜24px 程度のゆったりした余白。「サマリー=ゆったり / 作業領域=密」の対比が操作頻度と重要度を表現している

### システム

- コンポーネントは少数の型の再利用で構成される: (1) 繰り返しユニット（キャラクターカード）、(2) チェックボックス+ラベル+数値バッジの行コンポーネント（デイリー/ウィークリー共通）、(3) セクションヘッダー（見出し左 + アイコンボタン群右寄せ）、(4) プログレスバー、(5) フローティング操作パネル
- 同一の行コンポーネントが3種のセクションで共通利用され、全ユニットが同一の内部構造を厳密に踏襲する。表示内容の個別差（タスクの有無）はあってもレイアウトの型は崩れない
- アイコンの意味（編集・並べ替え・検索）は画面全域で一貫
- 本プロジェクトへの翻訳: チェックセル・カウントセル・セクションヘッダー・追加行を統一コンポーネントとして3カテゴリ（デイリー/ウィークリー/マイルストーン）で使い回す

### CTA

- 明確な単一の主要CTAボタンを持たず、個々のチェックボックス操作自体が主要な行動である「実行型UI」。日常的に繰り返し使う作業画面として、派手な誘導より機能を優先した設計
- 編集・並べ替え等の準主要操作は 16px 程度の小さなアイコンボタンとしてセクション見出しの右に置かれ、テキストラベルを持たない
- 副CTA（管理系ボタン・ログインリンク）は枠線のみ・塗りなしで本文サイズ以下に抑え、視覚的重みを意図的に落としている
- 本プロジェクトへの翻訳: チェックセルを最大のクリック領域として最優先し、追加・並べ替え・設定は枠線のみ/淡色/ホバー表示で視覚的重みを一段落とす
